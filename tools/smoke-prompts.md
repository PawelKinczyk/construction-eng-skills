# Smoke prompts: one quick check per skill

Purpose: after any change to a skill, its references or its scripts, run the prompt for that
skill and check the "must show" column. Takes minutes, catches the changes that break the skill's
behaviour. The full set, with expected outputs, is in `tools/eval-checklist.md` (generated by
`tools/eval_runsheet.py`).

How to use
1. Run `python tools/build.py check` and `python tools/verify_skills.py` first: structural failures
   make the prompt tests meaningless.
2. Paste the prompt with the files it needs. Keep the project context (`PROJECT.md` or the
   project brief example) in the conversation.
3. Judge against the "must show" column, and against the red lines below.
4. Record the result in `tools/eval-checklist.md` or in the commit message.

Red lines that apply to every skill
- No invented clause numbers, prices, rates, model numbers, quantities, dates or names.
- Unknown values marked to verify, never filled from memory or from another project.
- Calculations run through a script, with inputs, formula and units shown.
- Law only from the official government domains listed in the jurisdiction file.
- Deliverable written in the language set in `PROJECT.md`.
- The skill says what it is not (not an approval, not a notice, not a legal opinion, not a price).

## Changes that need more than the smoke prompt

Run the full checklist (`tools/eval-checklist.md`) when the change touches:
- the trigger text in the frontmatter `description` (the agent's skill selection depends on it);
- the output format or the section order of a skill;
- a script's arguments, or the meaning of a value it prints;
- a shared reference in `shared/references/` (it is copied into every skill);
- the jurisdiction files' legal sources or the rules about law.

## Timing a change

A skill change is done when: the structural checks pass (`build.py check`, `verify_skills.py`),
the smoke prompt for that skill passes, and the commit message says which prompts were run.
