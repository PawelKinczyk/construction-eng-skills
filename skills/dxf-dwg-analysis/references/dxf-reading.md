# What a DXF or DWG file can and cannot tell you

## 1. Units and scale

| What | Where | Trap |
|---|---|---|
| Drawing units | header variable `$INSUNITS` | often unset (0 = unitless) or wrong; a drawing in metres with `$INSUNITS` = millimetres gives lengths 1000 times off |
| Measurement system | `$MEASUREMENT` (0 imperial, 1 metric) | does not define the unit |
| Insertion scale | `$INSUNITS` with `$DIMSCALE` | a block inserted at the wrong scale looks correct on screen, not in the data |
| Paper scale | paper space viewport | model space is in drawing units; the plot scale lives in the layout |

Always report `$INSUNITS` and the extents. Then check the extents: a 30 m building whose extents are 30 000 units is in millimetres; a 30 m building whose extents are 3 000 000 has a stray object or a wrongly scaled insert.

The script reports two extents. The full extents include entities on off or frozen layers and attribute text, so they can be larger than what is plotted (a frozen-layer block with its attribute text sticks out beyond the walls). The "visible" extents use only entities on layers that are on and not frozen. If they differ, say why before quoting a size.

## 2. Model space, paper space, layouts

- Counts default to model space, which is where design content sits.
- Paper space holds title blocks, viewports and annotations. A sheet's title block is therefore usually in paper space, per layout.
- A viewport shows model space at a scale: content visible in a viewport is not "in" paper space.
- Multiple layouts mean multiple sheets in one file. Report each layout with its name and paper size.
- Frozen or off layers still exist in the file. A count includes them unless the script filters them; state the choice, and never equate "in the file" with "visible on the plot".

## 3. Blocks and attributes

| Item | Meaning |
|---|---|
| Block definition | the template, stored in the block table, drawn once per file |
| Block reference (`INSERT`) | one instance placed in the drawing; the count of insertions is what matters |
| Nested block | a block containing another block; a naive count misses the components, a naive sum double counts |
| Anonymous block | generated by dimensions, hatches, tables (`*D1`, `*U5`); exclude from symbol counts and say so |
| Dynamic block | one definition with parameters; instances can differ in geometry while sharing a name |
| Attribute | a tag with a value on the insert (room number, equipment tag, type code) |
| Constant attribute | the same value for every insert; useful for a type code, useless for a tag |
| Xref | an external reference to another file; readable only if the file is present and resolved |

Rules
- State which block names were counted, and the filter used.
- Report inserts on locked, frozen or off layers separately: they are often leftover options, not built work.
- For a symbol count used later for pricing or selection, compare against a schedule or drawing reading. Two different counts mean one of them is wrong - find out which before using either.

## 4. Entities that spoil a count

| Entity | Why it matters |
|---|---|
| Proxy entities | custom objects from another application; their content is unreadable and the count is low |
| Text as geometry | text exploded into lines: the text is gone, only the shape remains |
| Duplicated entities | copied on top of each other, common after hurried edits; a count is not a quantity |
| Construction lines and guides | infinite lines across the drawing; they set extents far outside the building |
| Hatches and dimensions | anonymous blocks and many small entities; excluded from symbol counts |
| External references unresolved | the content is missing entirely from the file as received |
| A drawing inserted as a block | doubles the entity count of whatever it contains |

## 5. Revision comparison between two CAD files

What a file comparison can tell you:
- layers added, removed, renamed, or changed in state;
- entity count change per layer and per entity type;
- block insert count change per block name;
- block insert count change per block name and per layer (a block moved to another layer shows only in the per-layer count);
- attribute value changes, matched by the `TAG` attribute of each insert (blocks without a `TAG` attribute are compared as sets of values; duplicate TAG values are paired in file order, so treat them as a finding rather than a change);
- units and extents changes, which catch a rescaled or re-originated drawing.

What it cannot tell you:
- what a changed line means (a moved duct, a duplicating view, or a deleted note);
- whether the change is design or drafting;
- whether a removed block was deleted or just moved to another layer or file.

So: report the file-level changes as evidence, and require a drawing reading for the meaning. Say clearly which of the two you did.

## 6. DWG

DWG is a closed format. Read it by converting a copy to DXF with the ODA File Converter (free, from the Open Design Alliance), then analyse the DXF.

- Convert a copy, never the original, and keep the converter output with the report.
- The output format matters (for example ACAD2018 DXF); record it, because newer formats preserve more custom objects.
- Record the converter version: different versions keep or drop different custom objects, which changes proxy counts.
- A DWG that converts with warnings gives a report with warnings. Do not present a partial conversion as complete.
- If the converter is not installed, say so and ask for a DXF export from the authoring tool, or convert on another machine. Do not guess at the content.

## 7. Reporting rules

- Every number comes with: file name, file date, unit setting, model or paper space, and the filter used.
- A count is not a quantity. Before it is used for money or for a selection, check it against a schedule or a drawing reading and say who confirmed it.
- Layer and block naming findings go to `project-standards` for the verdict.
- Never write into the user's CAD files. Output CSVs, JSON and Markdown next to the report, in a new file.
